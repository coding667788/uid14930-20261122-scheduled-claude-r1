我们准备启用可同步的通行密钥。旧审计器按服务器收到的顺序比较计数，现场经常把合法的多设备登录判成凭证异常。请写一个离线取证程序，按这套业务规则重新裁定。输入是通过预校验的虚构登录回执、可信登记及同步记录；断言签名用布尔值标示，不接入任何真实身份服务。

凭证有独立的登记代次，一个代次有多个可用副本，副本 ID 可在更换设备后重新出现，但设备实例不能混用。每次成功认证须能分配给与证据相符的一个副本实例。未给定副本的回执提供有限候选集合。每个副本的正计数必须按其可信偏序严格上升，不要求连续。计数为零只许可出现在明确登记为无计数器的实例上，同一登录失去确认后的接收重试以原请求指纹去重。同步可能创建已继承下界的新副本，记录绑定父实例及父已发出的某次回执。某回执跨过撤销节点后不能再用该副本。不同可信来源的事件偏序和观察期限叠加，服务器接收顺序仅作旁证。不同实例互不共享计数空间。输入中预先标明哪些回执必须真实、哪些可因观测错误剔除；缺失的签名或非法挑战绑定不可用任何排序补救。

需要两种报告。第一种为每条回执判断「所有可行恢复都保留」「只在部分恢复中保留」「无可行恢复能保留」，保留的见证必须给出一套全局事件顺序及副本分配。第二种求能解释剩余记录的最小异常集，按剔除代价总和、条数、升序回执 ID 决胜；有多套等价解释时，同时列出在所有最优解释里都必然异常的记录。对于没有任何可行解释的输入，指出固定记录冲突。支持 36 条回执、8 个副本、每条最多 3 个候选实例，说明状态如何考虑未完成的同步依赖，并用小规模独立穷举核对。至少复现倒序收件但可解释、同计数由不同副本签发、身份更换后错误串代、合法回执的异常判定取决于另一条记录、以及最低代价解有多种但必要异常为空。

把程序入口做成 python -m passkey_audit CASE.json，在 Windows 原生 Python 3.12 和 CPU 上用标准库从空目录编写。输出确定的 UTF-8 JSON，格式问题报告字段路径和错误码。交付可立即运行的本地虚构案例，README 写清输入输出，附可由 unittest 运行的断言测试。
